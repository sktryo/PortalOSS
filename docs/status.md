このドキュメントは、Portal 再実装の現在の状態を「実装済み / 簡易実装 /
未実装」で整理したものです。設計の詳細は
[architecture.md](architecture.md) を参照してください。

x86_64 用の `devtools/bin/vpc` を実行できず、フルビルドと実機確認は

ビルド確認を行う場合は、x86_64 Linux + podman または Windows +
Visual Studio 2022 の環境で [README](../README.md) の手順を実行してください。

## 3. 既知の制限・問題

### 3.1 ポータル配置

- 表面の材質を判定していないため、本来ポータルを置けない面にも設置できます。
- `FindPlacementExtents()` は平面上の 4 方向 trace のみで、開口部の形状を
  厳密に求めるものではありません。
- ポータル同士が近接・重複する場合の配置制限はありません。

### 3.2 trace

- BSP の穴あきを使わないため、ポータル越しの可視性・衝突は近似です。
- レイがポータル平面を跨ぐたびに epsilon を消費するため、非常に長い
  連続ポータル通過では誤差が蓄積します。
- ポータル越しのヒット位置はリンク先空間の座標で返します。
  呼び出し側が元の空間の座標を期待する場合は注意が必要です。
- `UTIL_Portal_TraceEntity` はスイープを 1 回転送するだけで、
  ポータル通過後の形状・角度変化を厳密には扱いません。

### 3.3 移動・物理

- プレイヤーのポータル通過は未実装です。`CPortalGameMovement` はストック
  `CHL2GameMovement` を継承し、オーバーライドしていません。ポータル開口部は
  設置された壁と同じ扱いで衝突します。以前の部分実装は移動 trace のみを
  ポータル越しに延長し、速度・視点角の変換を試みていましたが、プレイヤー
  位置をリンク先へテレポートする処理がなく、壁抜けを許す恐れがあったため
  削除しました。実装する場合は `ProcessMovement()` 内でポータル平面を
  検出し、`mv->SetAbsOrigin()` と `mv->m_vecVelocity` を変換してから
  移動を完了させる必要があります。
- ポータル内での押し出しや段差処理も完全ではありません。
- vphysics プロップはフレーム終了時にテレポートする方式です。
  高速で移動するオブジェクトや、ポータル平面に沿った接触は
  正しく扱えない場合があります。
- ポータル越しの連続した物理空間(シャドウクローン)は実装していません。

### 3.4 描画

- ステンシル描画は実装されていますが、実機での画質・深度・ステンシル
  クリアの検証は行われていません。
- ポータル表面は `debug/debugvertexcolor` で描画しており、
  Portal 本編のポータルマテリアル/シェーダーは使用していません。
- `portal_render_targets_enabled` は `_rt_Portal1` / `_rt_Portal2` への
  描画を有効にするもので、通常のステンシル描画とは別経路です。
- 水面・フォグ・空の連携はフックのみで、見た目の検証は未実施です。

### 3.5 ゲームプレイ

- Portal 本編の HUD、字幕、実績、チャレンジモード、開発者コメントは
  実装していません。
- NPC はポータルを認識せず、ポータル越しのナビゲーションも行いません。
- `linked_portal_door` などのマップエンティティが未実装のため、
  該当するマップでは「クラスが見つからない」警告が出ます。
- セーブ/ロードは SDK の汎用機構に依存しており、ポータル状態の
  完全な保存・復元は検証していません。
