# 実装状況

このドキュメントは、Portal 再実装の現在の状態を「実装済み / 簡易実装 /
未実装」で整理したものです。設計の詳細は
[architecture.md](architecture.md) を参照してください。

## 1. 確認状況

| 項目 | 状態 |

| コードの静的レビュー | 実施済み |

| Windows でのフルビルド | **未確認** |
| ゲーム内での動作確認 | **未確認** |

このリポジトリの作業環境は aarch64 で podman が利用できないため、
x86_64 用の `devtools/bin/vpc` を実行できず、フルビルドと実機確認は
行えていません。コード変更は構文・API・データフローの静的確認に留まります。

ビルド確認を行う場合は、x86_64 Linux + podman または Windows +
Visual Studio 2022 の環境で [README](../README.md) の手順を実行してください。

## 3. 既知の制限・問題

### 3.1 ポータル配置

- 材質判定は `SURF_NODRAW` / スカイ面 / `tools/nodraw`・`tools/skybox`・
  `tools/noportal`・`tools/nolight` の拒否のみで、Portal 本編のような
  メッシュ指向(面の法線・面積)ベースの判定ではありません。
- `FindPlacementExtents()` は平面上の 4 方向 trace のみで、開口部の形状を
  厳密に求めるものではありません。
- 2 門(青/オレンジ)の固定ペア制限は本編と同じですが、同一ポータル上への
  再設置は既存ポータルを Fizzle して置き換わります。

### 3.2 trace

- BSP の穴あきを使わないため、ポータル越しの可視性・衝突は近似です。
- レイがポータル平面を跨ぐたびに epsilon を消費するため、非常に長い
  連続ポータル通過では誤差が蓄積します。
- ポータル越しのヒット位置はリンク先空間の座標で返します。
  呼び出し側が元の空間の座標を期待する場合は注意が必要です。
- `UTIL_Portal_TraceEntity` はスイープを 1 回転送するだけで、
  ポータル通過後の形状・角度変化を厳密には扱いません。

### 3.3 移動・物理

- プレイヤーのポータル通過は `CPortalGameMovement::ProcessMovement` の冒頭で
  実装しています。開口部進入は origin ベースの近似(壁面 26、床面 6 tile)
  であり、 hull 全体の開口部との交差を厳密には判定しません。そのため
  壁の薄い場所や狭い開口部では判定が粗くなります。
- 各ポータルペアに 0.25 秒の cooldown があり、出口から出るまで再進入を
  抑制します。
- ポータル内での押し出しや段差処理も完全ではありません。
- +USE 掴みはストック `player_pickup` コントローラを使用するため、
  掴んでいる間はポータルガンがホルスターされます(本編ではガンが
  見えたままです)。+ATTACK で投げ、再 +USE でドロップします。
- vphysics プロップはフレーム終了時にテレポートする方式です。
  高速で移動するオブジェクトや、ポータル平面に沿った接触は
  正しく扱えない場合があります。持ち上げ中のプロップが持主と別に
  通過した場合はドロップします。
- ポータル越しの連続した物理空間(シャドウクローン)は実装していません。

### 3.4 描画

- ステンシル描画は実装されていますが、実機での画質・深度・ステンシル
  クリアの検証は行われていません。
- ポータル表面は `debug/debugvertexcolor` で描画しており、
  Portal 本編のポータルマテリアル/シェーダーは使用していません。
- `portal_render_targets_enabled` は `_rt_Portal1` / `_rt_Portal2` への
  描画を有効にするもので、通常のステンシル描画とは別経路です。
- 水面・フォグ・空の連携はフックのみで、見た目の検証は未実施です。

### 3.5 ゲームプレイ

- Portal 本編の HUD、字幕、実績、チャレンジモード、開発者コメントは
  実装していません。
- NPC はポータルを認識せず、ポータル越しのナビゲーションも行いません。
- `func_portal_orientation` / `env_portal_pathtrack` などのマップエンティティが
  未実装のため、該当するマップでは「クラスが見つからない」警告が出ます。
  `prop_portal_spawner` / `linked_portal_door` / `prop_button` は近似実装が
  追加されています。
- セーブ/ロードは SDK の汎用機構に依存しており、ポータル状態の
  完全な保存・復元は検証していません。
